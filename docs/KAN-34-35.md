# KAN-34 / KAN-35: sprawdzanie rozwiązania

`POST /student/tasks/{id}/check` przyjmuje wyłącznie `{"source_code": "..."}`
(1–102400 bajtów UTF-8). Korzysta z istniejących `require_role(STUDENT)`,
`check_origin` i `available_student_task`: DRAFT, archived oraz brak zadania dają
404 zgodnie z katalogiem. Odpowiedzi mają `Cache-Control: no-store`.
Nie zapisuje prób, ocen ani ukończenia zadania. Migracja bazy nie jest potrzebna.

## Architektura

Endpoint pobiera `TaskTest` z bazy, sortując po `position, id`. Serwis
`solution_check` waliduje definicje istniejącym schematem KAN-27 i kolejno ocenia
wszystkie testy. Nie przerywa serii po błędzie programu ani niezaliczonym teście.
Wspólny `Judge0Service.run_code` odpowiada za wersję Pythona, CPU, pamięć,
wall time, wyłączoną sieć, polling i obsługę błędów infrastruktury.

Każde wykonanie ma istniejący deadline
`max(judge0_max_wait_seconds, max(5, cpu + 3) + 5)`.
Deadline całej serii wynosi `min(300, 5 + liczba_wykonań * deadline_wykonania)`
sekund. Wszystkie testy strukturalne współdzielą jedną dodatkową analizę AST
w Judge0, wliczaną do liczby wykonań. Duża seria może wyczerpać
pięciominutowy budżet: API zwróci wtedy 504 bez częściowego podsumowania.
Usługa nie rezerwuje pięciu sekund dla całej serii.

## Typy testów

- **INPUT_OUTPUT:** kod i zapisane `input_data` trafiają do Judge0. Backend porównuje
  stdout z `expected_output`. Zamienia CRLF na LF i usuwa wyłącznie końcowe LF
  z obu stron; zachowuje spacje, wcięcia i puste linie wewnętrzne. Obecny model
  KAN-27 nie ma pola checker ani obsługi contains/regex. Nie dodano równoległego
  modelu porównywania ani migracji rozszerzającej konfigurację nauczyciela.
- **FUNCTION:** backend tworzy ZIP `additional_files` z `solution.py` oraz kontrolowany
  skrypt uruchamiający `runpy.run_path` **wewnątrz Judge0**. Nazwa funkcji i lista
  argumentów JSON jednej próby są podawane przez stdin. Wywoływana jest funkcja
  z globalnej przestrzeni modułu przez `namespace[name](*arguments)`; blok
  `if __name__ == "__main__"` nie jest uruchamiany. Wynik wraca w protokole JSON
  z losowym znacznikiem pojedynczego wykonania. Oczekiwana wartość pozostaje
  wyłącznie na backendzie, gdzie wykonywane jest porównanie zagnieżdżonych
  wartości JSON (boolean nie jest równy liczbie). Brak wyniku, niefinitywna wartość,
  niepoprawny JSON, wyjątek lub timeout oznaczają failed.
- **STRUCTURAL:** zaufany, samodzielny analizator `structural_runner.py` jednokrotnie
  parsuje kod modułem `ast` w Judge0, dokładnie w `task.python_version`, bez
  wykonywania kodu ucznia. Kod jest danymi stdin, nigdy importowanym modułem ani
  częścią skryptu analizatora. Analizator zwraca wyłącznie fakty AST w JSON;
  reguły (także hidden) pozostają na backendzie, który ocenia fakty.
  Analiza odbywa się przy pierwszym teście STRUCTURAL, z cache w obrębie serii.
  Sprawdza FUNCTION_EXISTS (także async), CLASS_EXISTS, CALLS_FUNCTION
  (nazwa prosta albo ścieżka atrybutów, np. `math.sqrt`), USES_FOR (także async),
  USES_WHILE i USES_IF. Komentarze i literały tekstowe nie zaliczają reguł.
  Błąd składni powoduje failed testów strukturalnych z bezpiecznym komunikatem.
  Awaria analizatora, błędny protokół i przekroczenie jego limitu są błędami
  technicznymi 502/504, a nie niezaliczeniem rozwiązania.

## Kontrakt odpowiedzi

Przykład dwóch testów, w tym ukrytego:

```json
{
  "passed": 1,
  "total": 2,
  "all_passed": false,
  "results": [
    {
      "number": 1,
      "position": 2,
      "test_type": "INPUT_OUTPUT",
      "is_public": true,
      "status": "passed",
      "details": {
        "name": "Dodawanie",
        "config": {"input_data": "2 3", "expected_output": "5"},
        "actual_output": "5\n",
        "has_actual_result": false,
        "execution": {"status": "completed", "stdout": "5\n", "exit_code": 0, "time": 0.01}
      }
    },
    {
      "number": 2,
      "position": 7,
      "test_type": "FUNCTION",
      "is_public": false,
      "status": "failed"
    }
  ]
}
```

Publiczne `details` zawiera nazwę i aktualną konfigurację KAN-27. Dla funkcji
zawiera `actual_result` oraz `has_actual_result` (rozróżnia brak wyniku od JSON null).
Przy JSON null pole `actual_result` jest pomijane przez serializer, a UI odtwarza
null na podstawie `has_actual_result`. Publiczny `execution` używa schematu
KAN-32/33, w tym statusu technicznego, czasu i diagnostyki. Dla funkcji stdout
protokołu nie jest prezentowany. Opcjonalne pola null są pomijane.

`passed` liczy wyniki ze statusem passed, `total` liczy wszystkie testy.
`all_passed` jest prawdą tylko dla niepustej serii z kompletem zaliczeń.
Pusta seria zwraca 0/0 i osobny komunikat w UI, bez sukcesu.

## Ochrona testów ukrytych

Dla hidden testu serwis nie tworzy `details`. Odpowiedź zawiera tylko numer,
pozycję, typ, widoczność i passed/failed. Nie zawiera nazwy, konfiguracji,
argumentów, oczekiwanego ani faktycznego wyniku, czasu, tracebacka, stderr,
stdout, wrappera ani tokena Judge0. Ten sam mechanizm dotyczy wszystkich typów
oraz błędów wykonania. Frontend dodatkowo ignoruje details testu ukrytego.

Każdy test funkcji dostaje osobny sandbox i wyłącznie argumenty tej jednej próby.
Nie otrzymuje oczekiwanej wartości ani pozostałych testów. Kod funkcji może
obserwować własne argumenty, co jest konieczne do jej wywołania; jego wyjście
i diagnostyka dla hidden nigdy nie są publikowane uczniowi. Protokół wewnątrz
sandboxa nie stanowi odrębnej granicy bezpieczeństwa wobec kodu ucznia.

Frontend używa zwykłych węzłów tekstowych React. Diagnostyka publicznych błędów
ponownie wykorzystuje `ExecutionResult` i parser `pythonError` z KAN-33.

## Błędy i UX

Wyjątek Pythona lub timeout programu to failed konkretnego testu. Niedostępny
Judge0, nieobsługiwane środowisko, niepoprawna konfiguracja lub timeout techniczny
przerywają sprawdzanie odpowiedzią 502/503/504 bez mylącego 0/N.
UI pokazuje bezpieczny komunikat techniczny i umożliwia ponowienie.

„Sprawdź rozwiązanie” wysyła aktualny kod bez lokalnego stdin. Osobny stan,
blokada przycisku i synchroniczny ref chronią przed wielokrotnym klikaniem.
Nowe sprawdzanie usuwa poprzedni wynik. UI zachowuje kolejność odpowiedzi,
pokazuje podsumowanie, publiczne szczegóły i neutralne statusy hidden.
„Uruchom kod” zachowuje dotychczasowe działanie.

Karta wyników odzwierciedla układ Figma `217:6127`: licznik w nagłówku,
okrągłe ikony i etykiety statusu oraz zwarta lista z krótkim podglądem.
Publiczne wiersze można rozwinąć, aby zobaczyć pełne wartości i diagnostykę;
hidden nie ma rozwijanych szczegółów. Przycisk sprawdzania znajduje się
pod przyciskiem „Uruchom kod”. Etykieta „Sprawdzono” opisuje wynik lokalnego sprawdzenia;
nie oznacza wysłania rozwiązania ani przyznania oceny.

## Walidacja i ograniczenia

Testy jednostkowe/API obejmują porównania, kolejność, limity, wszystkie reguły AST,
funkcje i protokół JSON, brak wycieku hidden, role, widoczność i błędy techniczne.
Testy PostgreSQL dodatkowo obejmują zapis i zmianę kolejności przez API nauczyciela
oraz READY/DRAFT/archived. Testy UI obejmują loading, blokadę, podsumowania,
publiczne dane i błędy, ukryte dane, ponowienie oraz zastąpienie wyniku.

Obsługa funkcji wymaga standardowego `additional_files` Judge0 (ZIP).
Analiza struktury wymaga dostępnego Judge0 również dla serii zawierającej
wyłącznie testy STRUCTURAL; parser backendu nie jest używany jako fallback.
Analiza struktury jest syntaktyczna:
wywołanie w nieosiągalnym kodzie spełnia regułę, alias importu nie jest rozwiązywany.
Funkcje przyjmują argumenty pozycyjne JSON i muszą zwracać wartość JSON;
nie dodano obsługi async functions, kwargs ani dowolnych obiektów Pythona.

CI osobno uruchamia testy samodzielnego analizatora na Pythonie 3.11–3.14,
w tym regresję składni t-string wprowadzonej w 3.14.
Test HTTP rzeczywistych interpreterów Judge0 można uruchomić z katalogu backendu:
`TEST_JUDGE0_URL=http://127.0.0.1:2358 python -m pytest tests/test_structural_judge0_integration.py -q`
(w PowerShell zmienną należy ustawić przez `$env:TEST_JUDGE0_URL`).

Poza zakresem pozostają zapisy prób, historia submissionów, oceny, punktacja,
ukończenie zadań, odblokowywanie, rankingi, analityka, AI hints i streaming wyników.
